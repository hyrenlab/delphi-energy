# Verification and limitations

Maintenance verification on 2026-09-08 used local Python 3.14.4, standard library
only. All 13 offline unit tests passed, as did the CLI dry-run, `--describe`, and
`examples/offline.py`. No paid providers, notification webhooks, or personal
ledger files were accessed. CI is configured for Python 3.10–3.13; its remote
results must be checked after publication and are not claimed here as completed.

## What is checked

- Lite flow has five scripted calls and produces a brief/action without writes.
- Standard flow passes the evidence review into Judge. Round-2 stays explicitly
  supplementary, with a visible warning in both brief and ledger.
- High-stakes flow passes dissent to Judge and counts both dissent calls.
- Estimated budget boundaries: below 80%, warning at 80%, skipping at 100%.
  Judge still runs after exhaustion, demonstrating the documented soft limit.
- Explicit model prices, labeled fallback rates, zero-cost model support, and
  rejection of invalid budgets, malformed prices, negative/NaN/infinite rates.
- Fenced JSON objects, non-object rejection, Judge repair success and failure;
  failed repair preserves raw text and does not generate an action.
- Dry-run requires no adapters and writes no ledger.

Reproduce from the repository root:

```bash
python3 -m unittest discover -s tests -v
python3 delphi.py "preview" --dry-run --no-vault --no-notify --no-stream
python3 delphi.py --describe
python3 examples/offline.py
```

The checked-in `examples/offline-transcript.md` was generated by the last command.
Its responses and token usage are synthetic. Wall clock/date fields vary per run.

## Boundaries and known gaps

This is a sequential prompt workflow, not an externally grounded research engine.
There is no independent web retrieval or claim-to-source validation. Evidence
grades, confidence frequencies, and factual whitelists are model/user assertions.
They can be wrong and should not be interpreted as calibrated guarantees.

The parser validates that output is a JSON object, not the full semantic schema.
Malformed nested fields can still fail rendering or subsequent stages. Provider
errors degrade to text; a failed Judge may leave no brief even though the CLI
returns success. SDK compatibility, auth, timeouts/failover, live model quality,
notification delivery, and dependency security have not been integration-tested.

Budget figures use configured token rates or disclosed hypothetical assumptions.
They omit provider-specific billing adjustments and cannot account for failed
requests without returned usage. Multi-call stages and Judge may overrun the soft
budget. Model quality, latency, factuality, and cost require a future benchmark
with dated configuration, prompts, source evidence, and redacted provider traces.

Round-2 questions are stored after Judge and do not revise the action. A new run
is not guaranteed to retrieve them. Review the ledger and explicitly include any
important unresolved question in a follow-up run.
